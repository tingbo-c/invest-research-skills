# A股事件即时解读

> **目的**:对单一新事件做**轻量即时反应**——评估它对原判断/原 thesis 的影响(增强 / 削弱 / 无关 / 重写),并检验催化剂是否已被 priced in(利好不涨 = 已透支)。
> **专治 A股痛点**:消息满天飞、小作文当公告用、利好兑现即见顶。本 skill 负责分清"事件真伪与权威性"+"这波催化是不是已经炒完"。

**与其他 skill 的边界**:
- 本 skill = 「插队 alert」:单个新事件触发,5-10 min 出结果
- 题材链 `theme-chain-context` B 模式 = 整条产业链/题材的事件;单股事件用本 skill
- `research-review` = 下游,审查本解读本身

---

## 触发场景

| 用户说 | 自动识别 |
|---|---|
| "某公司发了业绩预告,是利好吗" | event + 标的 |
| "解读一下某公司这次财报/重大合同公告" | event + 标的 |
| "集采开标了,对某公司什么影响" | event + 标的 |
| "对照原结论,这条新闻意味着什么" | event + 标的(含对照意图) |

**触发模糊时**:
- 没指定标的 → 主动反问"主要分析哪只票?还是整条题材链?"(后者走 theme-chain B 模式)
- 用户给的是片段/转述 → 主动 WebSearch 找原始公告来源,不只接受用户描述

---

## 工作流(5 步)

### Step 1:事件提取 + 权威性分级

**事件提取**:
- 从用户输入提取关键事实
- **强制 WebSearch** 找原始来源(优先巨潮/交易所公告原文),验证发生时间、当事方、官方表述
- A股标的用 6 位代码

**权威性 3 级分类(A股口径)**:

| 级别 | 类型 | A股例子 |
|---|---|---|
| **Class A** | 官方一手来源 | 交易所/巨潮公告(定期报告、业绩预告/快报、重大合同、权益变动、问询函回复)、证监会/部委政策文件、集采/招标官方结果 |
| **Class B** | 二手报道 / 分析 | 财联社/证券时报/上证报报道、券商研报、行业协会数据、交易所互动易回复(半官方,仍需核) |
| **Class C** | 情绪 / 传闻 | 股吧/雪球/社交媒体、小作文、未证实传闻、"市场传闻""据悉" |

**Hard Rule**:Class B / C 信息不能当 Class A 用。**A股小作文盛行,一手公告未证实前,传闻一律 Class C**;降权不代表不读,但必须明确标注。

### Step 2:Priced-in 检验(C6 核心)

如能获取事件后市场反应数据:

| 现象 | 含义 |
|---|---|
| 利好公告后不涨 / 高开低走 | 已 priced in 或预期透支(催化已炒完) |
| 利空公告后不跌 / 低开高走 | 利空出尽 / 已 priced in 风险 |
| 反应与事件性质一致 | 趋势加强(市场认同事件性质) |
| 涨停/跌停或大幅异动(放量) | 新增量信息(市场原本没预期到) |
| 一字板后开板放量、连板后分歧 | 情绪见顶信号,催化接近兑现 |
| 无显著反应 | 事件可能无关,或市场 misread |

**A股特别注意**:涨跌停制度下,"利好兑现即见顶""见光死"极常见——利好落地后的走势比利好本身更说明 priced-in 程度。
**注**:无价格数据可获取时,明确标注"无法验证 Priced-in 状态",**不编造**。

### Step 3:对核心判断影响评估(4 类必选其一)

| 类别 | 含义 |
|---|---|
| **增强** | 事件验证了某项原判断(如原判"产能放量"+ 公告新签大额订单) |
| **削弱** | 事件挑战了某项原判断(如原判"毛利稳定"+ 业绩预告大幅下修) |
| **无关** | 噪音,不实质影响结论(媒体猜测 / 短期波动 / 与核心驱动无关传闻) |
| **重写** | 事件颠覆原判断,需重做(重大监管变化 / 核心客户流失 / 实控人变更 / 财务造假立案) |

**Hard Rule**:必从 4 类选 1。**允许判"无关"**——不是所有事件都重要,反事件膨胀(把"无关"判成"削弱/利好")是常见错误。

### Step 4:具体影响定位

**如有历史分析/深研卡片对照**:定位原结论的哪几项受影响 + 怎么影响(业务/竞争力/财务质量/题材受益/估值口径)。
**无对照基线**:用通用维度分析(业务/财务/题材/催化剂),并明确标注"无对照基线"。

### Step 5:(可选)复核 + 输出

- 正式输出时建议交 `../research-review/SKILL.md` 做对抗审查:权威性分级是否合理、影响评估是否过激/过缓、是否事件膨胀。
- 批量编排场景由编排层统一安排复核与归档。

## 6 项必含输出(用户可见)

```markdown
# {代码} 事件解读:{事件简述}
日期:YYYY-MM-DD(事件发生日)
事件来源:{原始公告 URL + date}
对照基线:{历史分析/深研卡片,如有;否则标"无对照基线"}

## (a) 事件事实
{完整事实描述 + 来源 URL + date}

## (b) 权威性分级
**Class A / B / C** —— {理由}

## (c) Priced-in 检验
{市场反应 vs 事件性质 / 或"无价格数据可验证"}

## (d) 影响评估 ⭐
**增强 / 削弱 / 无关 / 重写** —— {1-2 句解释}

## (e) 具体影响定位
{对照原结论,仅列受影响项;不受影响的统一标"无影响"}

## (f) 更新提示(非 actionable)
{哪部分结论应更新 + 怎么更新}
{不输出"建议买卖 / 建议调仓"}

---
**WebSearch 引用**:
- {URL 1, date}
- {URL 2, date}
```

### 机读输出块(默认附末尾,供深研卡片回填)

```yaml
event_impact:
  code: <6位代码>
  event: <事件简述>
  event_date: <YYYY-MM-DD>
  authority_class: A | B | C
  priced_in: 已透支 | 部分定价 | 未定价 | 无法验证   # C6: 催化剂是否已炒完
  impact: 增强 | 削弱 | 无关 | 重写
  new_risk: <事件触发的新风险或反证,具体>
  next_watch: <事件后需新跟踪的 1 个指标>
  sources: [{url, date}]
```

无法判断时填 `未知`/`无法验证`,不编造。

## Hard Rules

| 不允许 | 必须 |
|---|---|
| ❌ 仓位 / 目标价 / 入场点 / 买卖建议 | ✅ 事件来源 URL + date |
| ❌ 模糊"利好/利空"二元判断 | ✅ 权威性分级 Class A/B/C 必填 |
| ❌ 把 Class B/C(小作文/传闻)当 Class A 用 | ✅ 影响评估必从 4 类选 1 |
| ❌ 跳过 Priced-in 检验 | ✅ Priced-in 给出"已透支/部分/未定价/无法验证" |
| ❌ 默认所有事件都"重要"(事件膨胀) | ✅ 允许判"无关"是合法输出 |
| ❌ 编造无法验证的价格/数据 | ✅ 无法验证时明说"无价格数据" |
| ❌ 用训练数据下"当前"结论 | ✅ 强制 WebSearch 原始来源 |

## 输出原则

- 6 项 (a)-(f) hard requirement
- 影响评估必从 4 类选(避免模糊"利好/利空"二元)
- 权威性分级必填(A股小作文多,传闻一律 Class C)
- Class C / 判"无关"时可简短输出,避免噪音轰炸
- 无对照基线时用通用维度,明确标注
- 无价格数据时明说"无法验证 Priced-in",不编造
- 只分析不建议:不出仓位 / 目标价 / 买卖时点
